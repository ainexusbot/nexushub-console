# NexusHub Admin — подписки и статистика пользователей

## Что добавлено

В боковом меню появился **Subscriptions**, доступный администраторам и суперадминистраторам. В карточке организации появилась кнопка **Subscription & usage**.

Раздел использует существующую авторизацию, дизайн и английские названия интерфейса админки. Подписки и ограничения относятся к организации; статистика по пользователям показывает, кто именно расходует общий лимит.

### Список подписок

- Поиск организации и пагинация.
- Статус и текущий расчётный период в UTC.
- Переключение типа операции для просмотра использовано / лимит / резерв / доступно.
- Токены и число AI-запросов организации за текущий период.
- Переход в управление выбранной организацией.

### Карточка подписки

| Вкладка | Возможности |
|---|---|
| **Limits & access** | Восемь отдельных лимитов, безлимит, блокировки функций и организации, групповая блокировка всех анализов, даты подписки |
| **Users** | Поиск сотрудника по имени/email, сортировка по токенам, операциям или имени; использование по всем типам, токены, ошибки, резерв и последняя активность |
| **AI requests** | Каждый AI-вызов: пользователь, тип, модель, статус, input/output/total tokens, кэш, шаги, инструменты и время |
| **Operations** | Создания и генерации, списанные/зарезервированные единицы, статусы и восстановление старого зависшего резерва |
| **Periods** | Исторические периоды, их лимиты и использование, переход к запросам периода |
| **Change history** | Администратор, дата и конкретные изменённые настройки; история восстановления резервов |

В Users откройте имя сотрудника или кнопку со стрелкой. Появится фильтр этого пользователя в AI requests. При переходе в Operations он сохраняется. Крестик на фильтре возвращает статистику всех пользователей.

Период можно переключить между текущим месяцем, предыдущими периодами и всей историей. Верхние четыре карточки всегда относятся к **организации и текущему периоду**; карточки внутри AI requests относятся к выбранным фильтрам.

Лимиты действуют после **Save changes**. Безлимит отправляется как `null`, нулевой лимит запрещает новые операции. При включении блокировки появляется подтверждение. Разблокировка не меняет сохранённый лимит.

Черновик настроек сохраняется при переключении вкладок. При конфликте правок другого администратора черновик остаётся на экране, а повторная отправка старой ревизии блокируется: используйте **Discard draft and load latest settings**, затем внесите правку заново. Обновление страницы с несохранёнными изменениями требует подтверждения. Чтобы восстановить зависший резерв, сначала сохраните или сбросьте черновик настроек.

## Точность статистики

- **Operations** в таблице Users — число операций журнала. Массовая загрузка нескольких компаний является одной операцией с несколькими единицами расхода. Разверните **Usage by type**, чтобы увидеть точное списание по каждому из восьми типов.
- Расход операций и AI-вызовы агрегируются отдельно: несколько AI-вызовов в одной операции не умножают количество созданных сущностей или писем.
- Сотрудник без активности отображается с нулями. Бывший участник остаётся в истории своей прежней организации, если у него была активность за выбранный период.
- После полного удаления пользователя из БД его ID обнуляется существующим FK. Такое использование сохраняется в общей строке **Deleted users (combined)**; восстановить имя удалённого пользователя из этих данных нельзя.
- Токены выводятся без потери точности больших чисел. Кэш входит в input и не прибавляется к total повторно.
- **Usage incomplete** означает, что полный расход провайдер не сообщил или запрос не завершился. Это не нулевой расход.
- Старые консольные логи до включения учёта подписок не переносятся в статистику автоматически.

## Установка

Обновляйте **оба репозитория** из текущих архивов: admin и backend subscriptions v2.

1. Если миграция подписок из предыдущей версии ещё не применена, выполните на backend:

   ```bash
   psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -1 -f db/migrations/20260906_subscriptions.sql
   ```

   Если она уже применена, **новая миграция не требуется**. Персональная статистика использует сохранённые `user_id`; структура БД в этом обновлении не менялась.

2. Обновите backend до приложенной v2 и соберите его обычной командой. Эта версия добавляет endpoint пользователей, фильтры по пользователю/типу и имена в журналах.
3. В admin установите зависимости и соберите проект:

   ```bash
   pnpm install --frozen-lockfile
   pnpm test:subscriptions
   pnpm build
   ```

4. `VITE_API_BASE` должен указывать на корень вашего backend без `/api`. Переменная подставляется во время сборки. Если она не задана, сохраняется прежний адрес Railway из `src/utils/api.js`.
5. Откройте **Subscriptions** под ролью `admin` или `super_admin`. Прямой URL `/subscriptions/:organizationId` также проверяет роль; сами API защищены backend.

Не заменяйте `src/utils/api.js` отдельным клиентом: раздел уже использует общий Bearer token и обновление сессии через refresh cookie. Новый production-пакет для интерфейса не нужен; добавлены только dev-зависимости для компонентных тестов.

## Новые возможности backend API

- `GET /api/admin/subscriptions/:organizationId/users?periodId=&search=&sort=tokens|operations|name&limit=25&offset=0` — `{ users, total, limit, offset }`.
- `GET .../usage` принимает дополнительный `userId`.
- `GET .../operations` принимает дополнительные `userId` и `metric`.
- В обоих журналах и истории изменений есть `userName`, `userEmail`.
- `userId=deleted` выбирает совокупную историю удалённых пользователей.
- Объект подписки содержит `canEditAnchor`: после первой операции поле даты старта заблокировано в интерфейсе.

Полный контракт базовой подписки находится в backend: `instructions/SUBSCRIPTIONS.md`.

## Что проверено

- Сборка admin и backend.
- 11 компонентных тестов React/JSDOM: навигация, права, лимиты, безлимит, подтверждение блокировок, конфликты, черновики, пользователь/период, восстановление резервов, ошибки сети и устаревшие ответы.
- 14 проверок backend на PGlite, включая статистику пользователей, несколько AI-вызовов в одной операции, бывших/удалённых участников и изоляцию организаций.

JSDOM проверяет поведение компонентов, но не геометрию рендеринга. Визуальная проверка не выполнена: браузер текущей среды запрещает открывать локальные страницы. PGlite использует одно соединение; тест конкуренции нескольких соединений обычного PostgreSQL запускается по инструкции backend. Реальные платные AI-вызовы не выполнялись.
